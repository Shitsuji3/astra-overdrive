# ボスを小さくして動かした（2026-09-12）

ユーザー依頼：「ボスのサイズをプレイヤーよりちょっとだけ大きいくらいのサイズに変更して。
もっとちょこまかと動いていいです。」

結果：8体すべての当たり判定をプレイヤー（24×40）の1.25〜1.8倍に縮めた。絵はその体に合わせて
自動で縮む。技と技の間、ボスは立ち止まらずに動き回るようになった。

## 1. 大きさ

| ボス | 変更前 | 変更後 | プレイヤー比 |
|---|---|---|---|
| WARDEN | 100×110 | 34×50 | 1.42 / 1.25 |
| TIDEBREAKER | 104×112 | 36×52 | 1.50 / 1.30 |
| COILHEAD | 100×108 | 34×50 | 1.42 / 1.25 |
| ASHMAW | 108×116 | 38×54 | 1.58 / 1.35 |
| NULLPRIEST | 94×104 | 32×48 | 1.33 / 1.20 |
| GRAVELOCK | 122×126 | 44×58 | 1.83 / 1.45 |
| SPARKWIDOW | 88×98 | 30×44 | 1.25 / 1.10 |
| OBSIDIAN CROWN | 112×120 | 40×56 | 1.67 / 1.40 |

体格の順位は変えていない。GRAVELOCK が最大、SPARKWIDOW が最小のまま。

### 絵の合わせ方を変えた
以前は絵を `min(幅×1.5, 高さ×1.35)` の枠に収めていた。この式は **幅で決まる**ので、
体を小さくすると絵の高さまで一緒に縮み、頭が当たり判定の上端より下に来てしまう。

いただいた絵はどれも横長（縦横比1.12〜1.50）で、翼や脚が左右に広がっている。
そこで **高さだけで倍率を決め、幅は絵の比率に任せる**形にした。

    倍率 = 体の高さ × 1.16 ÷ 絵の高さ
    足元を体の底に、左右は体の中心に合わせる

当たり判定は機体の胴だけを囲み、広がった脚や翼ははみ出す。翼に弾が当たらないのは
むしろ正しい。実際に描かれる大きさは横63〜97px・縦51〜67px。プレイヤーは24×48px。

共通の機体画像（WARDEN）も同じ考え方で `高さ÷110` 倍にした。体格100×110のときの
描画結果は変更前と1pxも変わらない。

### 技の出る位置
攻撃の発射位置に直接書かれていた数値（`b.y+30`、`b.x+80`、`cy+48`、`cx±30` など）を
すべて体に対する割合へ置き換えた。胸の高さは `b.h*.27`、砲口は `b.h*.18`、
波は `b.w*.55` 前方、という形。これで体格を変えても弾は機体から出る。
撃破時の爆発が歩く範囲、着地の衝撃波、セイバーの対ボス判定も同じ扱いにした。

## 2. ちょこまか動く

`_bossScurry()` を追加した。仕組みはこれだけ。

1. プレイヤーから 70〜220px 離れた位置を選ぶ。今いる側を選びやすく、22%で反対側へ渡る
2. そこへ `stepSpeed` px/秒 で歩く
3. 着いたら `think` 秒だけ休み、また選ぶ
4. 選ぶたび `hopChance` の確率で小さく跳ぶ。跳んでいる間も歩き続ける

選んだ先が今いる場所（＝壁際）なら反対側を選び直す。これを入れる前は壁に張り付いて
止まる時間が長かった。

突進中とスラムの跳躍中は動かない。技が体を持っている間は手を出さない、という決まりにした。
`leap` フラグでスラムの跳躍と普段の小跳びを区別している。**小跳びは着地しても衝撃波を出さない。**

### ボスごとの性格

| ボス | 歩く速さ | 跳ぶ高さ | 跳ぶ頻度 | せわしなさ |
|---|---|---|---|---|
| WARDEN | 210 | 300 | .34 | 1.0 |
| TIDEBREAKER | 190 | 285 | .30 | 0.95 |
| COILHEAD | 240 | 315 | .42 | 1.2 |
| ASHMAW | 170 | 265 | .22 | 0.8 |
| NULLPRIEST | 265 | 290 | .40 | 1.45 |
| GRAVELOCK | 155 | 360 | .30 | 0.7 |
| SPARKWIDOW | 300 | 300 | .46 | 1.7 |
| OBSIDIAN CROWN | 255 | 320 | .45 | 1.3 |

数値はすべて `assets/bosses.js` のエントリにある。エンジン側に個体の数字は無い。

### 実測（プレイヤーを置いたまま30秒×6回）

| ボス | 平均移動 | 接触被弾 | 立ち撃ちの弾道より上にいる時間 |
|---|---|---|---|
| WARDEN | 143px/s | 2.0回/分 | 10% |
| TIDEBREAKER | 131px/s | 2.0回/分 | 11% |
| COILHEAD | 161px/s | 2.0回/分 | 12% |
| ASHMAW | 121px/s | 2.0回/分 | 7% |
| NULLPRIEST | 180px/s | 2.0回/分 | 14% |
| GRAVELOCK | 120px/s | 2.0回/分 | 15% |
| SPARKWIDOW | 202px/s | 2.0回/分 | 17% |
| OBSIDIAN CROWN | 176px/s | 2.0回/分 | 13% |

プレイヤーの走りは190px/s なので、だいたい歩く〜走るくらいの速さで動き回る。

**跳んでいる最中は立ち撃ちの弾が下を通る。** 銃口は y=295、床は310なので、
体が18px以上浮くと弾道から外れる。最初は NULLPRIEST 23%・SPARKWIDOW 31% まで行ったので、
この2体の跳躍を下げて全体を7〜17%に収めた。セイバーは上方向に100px届くので常に当たる。
ジャンプ撃ちでも当たる。避ける相手として成立する範囲に留めたつもり。

## 3. 検証

`npm test` 全92項目合格。乱数が入ったので**10回連続で走らせて全部合格**を確認した。
追加したのは3項目。

- ボスがプレイヤーより大きく、かつ2倍以内に収まっていること。移動用の数値が全員分あること
- 技と技の間に動き回り、跳び、着地し、アリーナから出ないこと。**小跳びが衝撃波を出さないこと**
- 突進とスラムの間は動かないこと。スラムは着地で体を返し、本物の衝撃波を2つ出すこと

既存テストで直したもの。

- `tests/warden-baseline.json` を作り直した。体格が変わったので凍結した弾の位置も変わる。
  `tools/snapshot-warden.cjs` が `w:100,h:110` を直書きしていたのをやめ、ロスターから
  体を作るようにした。これで二度と実物とずれない。体格も凍結対象に加えた
- 武器のテスト2件（`combat-polish` と `mouse-combat`）は、ボスが動くようになったせいで
  2撃目が外れるようになった。これは武器の試験でボスの足さばきの試験ではないので、
  毎フレーム同じ位置に置き直す形にした
- スラムの追尾テストは90フレーム後の位置を見ていた。着地後は普段の移動が始まるので、
  **着地した位置**を見るように直した

実ブラウザーでの確認。

- `tests/browser-smoke.cjs` 17項目、`tests/browser-mouse.cjs` 12項目 合格、例外0
- `qa/release-check.cjs` 合格。公開用ビルドで404なし・外部通信なし・6技すべて・撃破演出2.23秒
- `qa/stage-playthrough.cjs` 9ステージ合格（BOSS RUSH の8体連戦を含む）
- 公開用ビルドは44ファイル 8.67MB、zip 8.37MB（変更前と同じ）

## 4. 残っていること

抜き残しは以前のまま。小さくしたぶん目立たなくなったが、絵の下端にある背景の帯は
4倍に拡大すると SPARKWIDOW などで見える。背景を無地にした元絵を `assets/bosses/src/` に
置いて `tools/cut-boss.py` を通し直せば消える。
