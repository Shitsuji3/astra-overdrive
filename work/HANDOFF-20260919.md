### コードの置き場所

- **行動ループ：** `assets/bosses.js` の各ボスの `routine`。
  - 1拍は `{ move, from, rest }`。その技が要る距離まで歩く → 溜める → 撃つ → `rest` 秒立ち止まる（隙）。
  - `tempo` で溜めの長さが伸び縮みする。
  - `pool`（使う技の一覧）は `routine` から自動で作られる。
- **技の中身：** `game.js` の `BOSS_MOVES`。技ごとの台本で、`b.move`（`t`、`dir`、`fired`、`pose`）に進み具合を持つ。終わると `finish()` でボスを休みに戻す。
- **溜めと技の長さ：** `game.js` の `combat.bossPatterns`（`tell`／`active`）。
- **地形の攻撃（`kind:'hazard'`）：**
  - 長方形の当たり判定を持つ。
  - `armIn` 秒は予兆だけで当たらない。当たっても消えず、セイバーで切り払えない（`solid`）。
  - `harmless` は落下地点の印だけ。
- **その他の弾の仕掛け：**
  - `hold`：落石を上で待たせる
  - `floorOnly`：途中の足場を抜けて床に落ちるので、印の上に必ず落ちる
  - `split`：玉が割れる
  - `turn`：戻ってくる丸鋸
- **NULLPRIESTが消えている間**（`b.phaseOut`）：自機の弾・セイバー・体当たりのどれも当たらない。
- **描画（`render.js`）：**

  | 何を | どこで |
  |---|---|
  | 元絵の向き（ASHMAWとNULLPRIESTだけ右向き、ほかは左向き） | `BOSS_DRAWN_RIGHT` |
  | 技のポーズ、溜めのポーズ | `BOSS_POSES`、`BOSS_TELL_POSES` |
  | 予告の線・印 | `BOSS_TELLS` |
  | 弾の絵 | `BOSS_SHOTS` |
  | 地形の攻撃の絵 | `bossHazardShape` |
  | 技に付く効果 | `BOSS_MOVE_FX` |
  | 技名 | `BOSS_MOVE_NAMES` |
  | 切り抜き画像に残る床の帯 | `BOSS_FLOOR_BAND` |

## 公開（GitHub Pages）の手順と注意

- **`main` へのpushは即、公開サイトへの反映になる。**
  - ユーザーが「反映して」と、**その変更について**明示した時だけpushする。
  - 前回の許可は次回の許可にならない。
- **pushの手段はGitHub Desktopの「Push origin」**（または、ユーザー自身に押してもらう）。
  - コマンドラインの `git push` は古い認証情報で止まる。
  - パスワードやトークンを入力したり、ファイルに書いたりしない。
- **GitHub Desktopの注意（09-17時点）：**
  - 版は3.6.6。
  - アプリが起動していないと名前で許可を取れないことがあった。先に「GitHub Desktop」を開いてから操作する。
  - 押す前に、画面上部で次の4点を確かめる。
    - Current repository が astra-overdrive
    - Current worktree が Astragemes
    - Current branch が main
    - Push origin の未送信件数
  - 押す直前にBraveが前面に出ることがある。そのときはGitHub Desktopを前面に戻して押し直す。
- **push後の手順：**
  1. `git ls-remote origin refs/heads/main` か `git -c credential.helper= fetch` で、GitHubの `main` が手元と同じになったことを確かめる。
  2. 公開サイトのファイル（例：`game.js?v=乱数`）に変更が載るまで待つ。09-17は最初の確認で載っていた。
  3. `GAME_URL` を公開URLにしてブラウザテストとQAを流す。
  4. CURRENT-STATEに「公開」ブロックを書いてコミットする。記録だけのコミットなので、pushは次の反映の時でよい。
