# ステージ追加とステージ選択（2026-09-11）

ユーザー依頼：「ステージ数を増やしていきます。今あるステージとは別に新たに作ってください。
ステージ選択もできるようにしてね。」

結果：ステージは3つになり、タイトルから選べるようになった。ステージごとに記録が残る。

## 1. まずステージをデータに切り出した

### 変更前
ステージは `game.js` の `_reset()` に直書きされていた。床・足場・敵の座標、ワールド幅、
ボスのアリーナ座標、チェックポイント、セクター名、操作ガイドの文言、ボスの体力が
すべてエンジンの中に埋まっていて、2つ目を足す場所が無かった。

### 変更後
`assets/stages.js` に `AstraStages` を新設し、1ステージ＝1エントリのデータにした。
エンジンは自分のレイアウトを持たない。ステージを足す作業は、この配列に1項目足すだけになる。

エントリの中身は id / name / subtitle / blurb / worldWidth / spawn / arena / boss /
checkpoints / sections / hints / pickups / build。

`AstraCombat.arena` と `AstraCombat.checkpoints` は定数をやめ、読み込んだステージのものを
指すようにした。これらを参照している既存のテストとQAはそのまま動く。

### 壊していないことの担保
切り出しの前に、今のエンジンが組み立てるレイアウトを丸ごと JSON に凍結した
（`tests/stage1-layout.json`、`tools/snapshot-stage1.cjs` で再生成）。
切り出し後、床57枚・敵28体・回復9個・アリーナ・チェックポイント・セクター区切りのすべてが
**1バイトも違わない**ことを確認し、その比較を `tests/stages.test.cjs` に常設した。
SIGNAL YARD をうっかり変えたらテストが落ちる。

### 途中で入れた不具合と、見つかった経緯
ボスの体力をステージ別にする書き換えで、波括弧の無い `if` の本体だけを置換してしまい、
ボス生成が毎フレーム走るようになった。プレイヤーが1フレームでアリーナへ吸い込まれ、
既存のチェックポイントのテストが落ちて発覚した。波括弧を足して修正済み。

### レイアウトの作り方
走りジャンプは穴149px・高さ84pxまで、ダッシュジャンプで208px。この数字を基準に、
149pxを超える穴にはすべて中継足場を置いた。高い足場は必ず、84px以内の下段から繋がるようにしてある。

MAGNET SPINE は最初、1区画あたり4枚の足場を等間隔で並べる作りにしてしまい、
全体図で見ると模様のように見えた。区画ごとに枚数と高さを変え、足場の無い区間も作って組み直した。
全体図は `qa/stage-map-<id>.png`。

## 3. ステージ選択

タイトルに「STAGE SELECT / ステージ選択」を追加した。選択画面には番号・名前・日本語名・
一行説明と、そのステージの記録（CLEAR / BEST スコア / BEST タイム）が並ぶ。

- ↑↓ で移動、Enter で開始、Esc で戻る
- クリックとタップでも選べる
- 選んだステージはタイトルに「SELECTED // 2. TIDAL REFINERY」と出る。
  START MISSION はそのステージを始める
- 記録は localStorage の設定と同じ場所に、ステージ id ごとに保存される
- 未知の id（保存が古い場合など）は最初のステージへ落ちる。起動不能にはならない

**解禁制にはしていない。** 最初から3つとも選べる。依頼が「選択できるように」だったため。
順番に解放したい場合は言ってほしい。

横向きスマホ（高さ390px）で3行が収まらなかったので、画面が低いときは説明文を隠して行を詰める
指定を足した。縦向きでもそのまま選べる。

## 4. 検証

`tests/stages.test.cjs` を新規追加（8項目）して `npm test` に組み込んだ。

- ステージ一覧が選択画面を作れる形になっている（id重複なし、必須項目、番号順、最後のセクターが
  取りこぼしを拾う、最後のチェックポイントがゲートにある）
- SIGNAL YARD が凍結した JSON と完全一致する
- ステージを起動すると、ワールド幅・アリーナ・チェックポイント・開始位置・初期セクター・
  リトライ地点がすべて入れ替わる。長さもアリーナ位置も互いに違う。ボス装甲は後ろほど重い
- 通常・イージー双方で、ボスがそのステージの装甲で出る
- リトライしても同じステージに留まり、チェックポイント未取得ならそのステージの開始地点へ戻る
- 知らない id は先頭へ落ちる
- セクター名と操作ガイドの帯の境界が正しい（ガイドは最後を過ぎたら消える）
- どのステージでも、全長にわたってセクター名が空にならない

`qa/stage-audit.cjs` は全ステージを回すようにした。穴の跨ぎ、足場の到達、敵の接地、
歩行兵の往復範囲、アイテムの到達、チェックポイントの接地と前進、セクターの切れ目、
そして開始地点からボスゲートまでの跳躍到達可能性を、3ステージそれぞれで検証する。
初回実行で MAGNET SPINE の浮いた回復1個とチェックポイント2個の宙吊りを検出し、修正した。

`qa/stage-playthrough.cjs` を新規追加。実ブラウザで選択画面から各ステージを起動し、
全長のセクター表示を歩き、アリーナに入り、ボスの6パターンを確認して撃破し、
選択画面に CLEAR が載ること、リロード後も記録が残ることまで見る。
公開用ビルドに対しても実行して合格している。

`npm test` 全81項目合格。

`assets/stages.js` をバンドルに追加した。28ファイル、8.12MB。
`qa/release-check.cjs` も合格（404なし・外部通信ゼロ・例外なし・スマホのパッド操作）。

## 6. 今後ステージを足すとき

1. `assets/stages.js` に1項目足す
2. `node qa/stage-audit.cjs` で通るまで座標を直す
3. `node qa/stage-playthrough.cjs` で実際に通す

エンジン・UI・ビルドはどれも触らなくてよい。選択画面は一覧から自動で作られる。
