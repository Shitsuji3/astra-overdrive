## 公開（GitHub Pages）の手順と注意

- **`main` へのpushは即、公開サイトへの反映になる。** ユーザーが「反映して」と、**その変更について**明示した時だけpushする。前回の許可は次回の許可にならない。
- **pushの手段はGitHub Desktopの「Push origin」**（または、ユーザー自身に押してもらう）。コマンドラインの `git push` は古い認証情報で止まる。パスワードやトークンを入力したり、ファイルに書いたりしない。
- **GitHub Desktopの注意（09-14時点）：**
  - プロセス名は `githubdesktop.exe`（app-3.6.5）。
  - ツールバーに「Current worktree」が増えたので、Push origin の位置が右にずれている。
  - 押す直前にBraveが前面に出ることがある。そのときはGitHub Desktopを前面に戻して押し直す。
- **push後の手順：**
  1. `git fetch` で `origin/main` が進んだことを確認する。
  2. 公開サイトのファイル（例：`game.js?v=乱数`）に変更が載るまで待つ（これまでは1分以内）。
  3. `GAME_URL` を公開URLにしてブラウザテストを流す。
  4. CURRENT-STATEに「公開」ブロックを書いてコミットする（記録だけのコミットなので、pushは次の反映の時でよい）。
- **公開版とローカルの見た目の違い：** リリース版は主人公の画像と背景をWebPに再圧縮して配るため、画面の画素は数%ずれる。光や炎の色の画素は一致する。
