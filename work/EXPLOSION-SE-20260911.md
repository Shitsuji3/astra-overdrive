# 撃破SEの作り直しとボス撃破の連続爆発（2026-09-11）

ユーザー指摘は2件。
1. 雑魚敵を倒したときのSEがしょぼい
2. ボスを倒したときは爆発数回 → 大爆発にしてほしい

## 1. 撃破SE

### 原因
`audio.js` の `sound()` にある音の表に **`explode` が入っていなかった**。
名前が見つからない場合は `m.select`（440Hz・0.09秒・矩形波）へ落ちる仕組みなので、
撃破音は選択音と同じ「ピッ」が鳴っていた。爆発の音ではなく、UI音が鳴っていたということ。

### 対応
バスター音（`blastBuffer`）と同じ方式で、爆発の実体をコードで合成して1度だけ作り、以後は使い回す。
外部ファイルは増やしていない。層は4つ。

| 層 | 中身 |
|---|---|
| crack | 弾ける瞬間の高域。ローパスの残りを取り出して8〜24msで切る |
| roar | ホワイトノイズ。カットオフが減衰と一緒に閉じていくので、遠ざかる轟音になる |
| deep | roar のさらに下の帯域。低く長く転がる |
| body / sub | ピッチが落ちる正弦波と、その下のサブ |

最後に反射を2回足して空間を作り、ピークで正規化する。

種類は2つ。

| 名前 | 長さ | ピーク | 用途 |
|---|---|---|---|
| explode | 0.62秒 | 0.62 | 雑魚撃破。短く明るい |
| boom | 2.10秒 | 0.92 | ボスの最後の大爆発。長く低い |

再生ごとに `playbackRate` を 0.93〜1.07 で振るので、連続で倒しても同じ音に聞こえない。
0.09秒以内に重なった場合は音量を0.55倍に落とす。同時撃破で音が割れないようにするため。

### 検証（`qa/explosion-sound.cjs`、`npm test` に組み込み済み）
実際の `audio.js` をスタブしたWeb Audioで動かして波形を取り出し、次を自動で確かめる。

- 音の長さとピークが想定どおり
- 前半にエネルギーが集中し、後半に向けて必ず減衰する（末尾は先頭の1/6以下）
- 60Hzから6kHzまでどの帯域にも実体がある（＝単音のビープではない）
- 重心が低い（低域2帯の合計 > 高域2帯の合計）
- 冒頭8msの高域が、0.2〜0.4秒の同じ帯域より十分明るい（＝立ち上がりに破裂音がある）
  実測は explode で176倍、boom で25倍
- 音の表へ落ちて素の発振器が使われた場合は、スタブが例外を投げて即失敗する

実測値は次のとおり。

| | 長さ | ピーク | RMSの推移（6分割） |
|---|---|---|---|
| explode | 0.62s | 0.62 | .184 → .097 → .048 → .031 → .021 → .011 |
| boom | 2.10s | 0.92 | .247 → .161 → .073 → .069 → .052 → .030 |

耳で確かめられるように WAV も書き出す。`qa/se-explode.wav` と `qa/se-boss-boom.wav`。

## 2. ボス撃破の連続爆発

### 変更前
体力が0になった瞬間に `active=false` にして、同じフレームで勝利画面へ渡していた。演出は無し。

### 変更後
`AstraCombat.bossDeath = { bursts: 9, blastAt: 1.55, end: 2.2 }` の段取りで進む。

1. **体力0の瞬間**：`_bossDown()` が走る。ボスは `down` 状態になり、攻撃も突進も止まる。
   場に残っていた敵弾は全部消す。画面が揺れ、爆発音が1回。
2. **0〜1.55秒**：小爆発が9回、機体の上をランダムな位置で歩く。
   間隔は `blastAt * ((i+1)/10)^0.72` で、後になるほど詰まっていく。
   1回ごとに白フラッシュと画面揺れ、`explode` 音。機体は震え続ける。
3. **1.55秒**：大爆発。中心に通常の2.3倍の爆発を1つ、その周囲に1.1倍を5つ。
   画面揺れは1.0（通常の撃破が0.18）、白い画面フラッシュ、`boom` 音。
   ここで機体の描画が消える。
4. **2.2秒**：勝利画面へ。得点800は従来どおり。

途中でボスに攻撃しても体力は0のまま増減しない。ボスからの接触ダメージも発生しない。

### 画面フラッシュ
`state.flash` は以前から存在して毎フレーム減衰だけしていたが、**どこからも設定されず、
描画もされていなかった**。今回これを大爆発で使うようにし、renderer に白のオーバーレイを足した。
減衰は毎秒1.0から3.0へ上げた。0.55から0.18秒で消えるので、尾を引かず一瞬光る。
低モーション設定ではフラッシュを出さない。

粒子の上限は240→320に上げた。大爆発だけで170個ほど使うため。

## 検証

`tests/fx-drops-boss.test.cjs` に3項目追加（計16項目）。

- 体力0の直後は `playing` のままで、ボスは即 `down` になり、敵弾が場から消える
- 小爆発が9回以上鳴り、そのすべての後に `boom` が1回だけ鳴り、最後に `victory` が来る
- 全体で 2.2秒 ±0.1秒
- 大爆発の粒子が小爆発の3倍を超え、機体の描画が消え、画面揺れとフラッシュが立つ
- 倒れたボスは追撃を受け付けず、二度と弾を撃たない

`tests/engine.test.cjs` の勝利判定も、1フレームで勝利する前提から演出を最後まで回す形へ書き直した。

`npm test` 全73項目合格。ブラウザ実機で browser-smoke 16項目・browser-mouse 12項目とも合格。
実機で雑魚撃破とボス撃破を音付きで通して、JS例外なし・2.23秒で勝利画面へ到達を確認した。

図：`qa/boss-death.png`（0.10秒から2.13秒までの8コマ）。再現は `qa/boss-death.cjs`。

## 手を付けていない点

勝利ジングル（`victory`）は従来どおり660Hzの矩形波1音のまま。大爆発の直後に鳴るので
物足りなく感じるかもしれないが、依頼の範囲外なので変えていない。
