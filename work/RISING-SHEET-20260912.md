# 斬り上げを11コマの絵コンテに合わせ直した（2026-09-12）

ユーザー依頼：対空の**コマ割り**（11コマのスプライト列）を渡され「できますか？」。

結果：**できた。技の骨組みを絵コンテ通りに組み直した。** 前の版はGIFから測って作ったが、
GIFでは読み切れていなかった動きが4つあった。コマ割りはポーズが1枚ずつ分離しているので、
GIFでは炎と重なって測れなかった部分が読めた。

`ゲームAstra/スクリーンショット 2026-09-12 191734.png` を複製したもの。
セル境界は列ごとのインク量の谷から出した。1枚だけ2体が接していて、谷（列78）で割った。

**参考の絵は公開リポジトリに入れていない。** `.gitignore` の `qa/*` が画像を落とすので、
`qa/rising-ref/` の中身は手元にだけ残る。他者のスプライトなので公開物には含めない。

### 色の切り分け
機体は暗紅色の装甲＋鋼色の板＋青いバイザー。炎はクリーム色の芯、橙の胴、純赤の縁。
**暗紅色と純赤は色相で数度しか違わない**ので、炎の縁が体のマスクに入り込んで重心を
上へ引っ張った。緑成分の比で切った。縁は緑が全く無く、装甲は常に赤の3分の1の緑を持つ。
炎の白熱部は灰色に見えて装甲板と紛れるので、青が緑より少ないかどうかで落とした。

## 2. 直した4点

### 体が前ではなく後ろへ反る
**これがいちばん大きい間違いだった。** 前の版は `spin` を +0.45（前へ26度）にしていた。
コマ割りを炎より下の行だけで測ると、空中の全コマで垂直から**後ろへ5〜20度**だった。
前へ倒していたので、跳び上がりではなく前のめりに転ぶように見えていた。符号を反転した。

**脚も畳んでいた。** `lift` を12〜14にして足を腰まで引き上げていたので、体が球になり、
球を回すと横倒しに見える。コマ割りでは**空中の全コマで足の位置が立ち姿と同じ高さ**に
あり、頭だけが9px高い。伸びた姿勢だった。`lift` を0〜3に落として脚を下ろした。

なお、GIFから測ったときに「垂直から30度」と読んでいたのは向きを確かめていなかった。
今回は炎より下だけを使ったので混入が無い。

### 振りかぶりが無かった
3コマ目の後方への炎が前の版に無く、いきなり足元から始まっていた。
`angle` の列を **3.05 rad（後方）→ 0.20（前方の床）→ −1.03（上前方）** と繋いだ。
数値が大きい方から小さい方へ回るので、炎は後ろから脚の間を通って前へ出る。体を横切って
飛ばない。

### 8〜11コマ目に何も無かった
前の版は0.62秒で技が終わり、そこから通常の落下姿勢だった。コマ割りは
**炎が手を離れて飛び、両腕が開き、短い刃を頭上に構えて落ちる**。

- 攻撃の尺を0.62秒から**0.78秒**へ延ばした。コマ割りでは頂点を2コマ過ぎても炎が全長で、
  0.62秒だと頂点で切れていた
- **落下の構えを第5段として足した。** これは攻撃ではない。`p.risingHold` という別の場に
  持たせたので、判定も出ないし入力も奪わない。着地・ダッシュ・次の斬りのどれでも即座に消える
- 炎は消える代わりに**短い刃へ縮む**。第4段の終わりと第5段の始まりが同じ形なので繋ぎ目が無い

### 炎が卵形だった
コマ割りの炎は**葉**の形で、手元は細く、5分の2ほどの位置がいちばん太く、先が尖る。
前の版は幅を最後まで持っていって丸く閉じていたので風船に見えた。制御点を内側に寄せた。

外縁が黒く見えていたのは、**体の後ろに描く輝きが前に描く赤い縁より外へ出ていた**ため。
半透明の赤が工場の暗い背景に直接乗って煤のように見えていた。輝きの範囲を縁と揃えた。
縁の色も上げてほぼ不透明にした。

さらに、コマ割りの炎は**噴き出す瞬間がいちばん長く**（5コマ目1.42、7コマ目1.29）、
上昇中に落ち着く。一定の長さだったので噴出が弱く見えていた。`surge` を足した。
8コマ目では炎の根が手から13px上がっている。手を離れて慣性で上がり続けている。
`tear` で根を上へ動かした。

## 4. 合わせていないもの

正直に4つ。

1. **炎の質感。** 参考はドット絵でぎざぎざに揺れ、軸に対して左右非対称。こちらは
   滑らかな層で軸対称。乱数でぎざぎざを出すとフレームごとにちらつくので入れていない
2. **8コマ目の離れた炎。** 参考では炎が完全に独立した物体として飛ぶ。こちらは根を
   上へ動かしているだけなので、高さが2.28に対し1.72しか出ない。別の飛翔物として
   作れば合うが、判定と描画が増える
3. **4コマ目のしゃがみ。** 参考は炎が2つ（後方の残りと前方の床）同時に出ている。
   こちらは炎の軸が1本なので床の分だけになり、輪郭が低い
4. **絵そのもの。** 参考のスプライトは使っていない。このゲームの機体と配色で描き起こした

## 5. テスト

`npm test` 108件合格（5件追加）。追加したのは絵コンテが足したものを固定するため。

- **炎が後方から出て、床を通り、それから上へ向かうこと。** 描かれた刃の向きを
  実際に読んで、後方（cos < −0.8）→ 前方かつ水平（cos > 0.8、|sin| < 0.5）→
  上前方（sin < −0.6 かつ cos > 0）の順を確かめる
- **空中の全コマで体が後ろへ反っていること**（spin が負、ただし −0.6 より浅い）と
  **脚が畳まれていないこと**（lift ≤ 4）
- **落下の構えが攻撃ではないこと。** 刃の届く位置に敵を置いて、削れないことを確かめる。
  同時に第5段の姿勢になっていること、斬りが終わっていること、着地で消えることも見る
- **ダッシュで即消えること**
- **リグが5段持ち、第5段が解けること。** 落下が長引いて構えが尽きたら刃が消えることも

browser-smoke 17項目・browser-mouse 12項目・saber-reach 合格。

## 6. 調整するには

- 上昇量・上昇時間 → `game.js` の `combat.rising`（`lift` と `gravity`）
- 攻撃の尺 → 同 `combat.rising.span`、落下の構えの尺は `combat.rising.hold`
- 体の反り・脚の下ろし → `assets/saber-rig.js` の `keys[3]` の `spin` と `lift` の列
- 炎の振り出しの道筋 → 同 `keys[3]` の `angle` の列（後方3.05から上前方−1.29まで）
- 炎の長さ・太さ・寿命・噴出の強さ・離れ方 → 同 `plume()`
- 炎の輪郭 → 同 `drawPlume()` の `tongue()`
- 落下の構えの姿勢 → 同 `keys[4]`
- 噛む回数と時刻 → `combat.saberHitTimes[3]`、倍率は `combat.saberComboPower[3]`
