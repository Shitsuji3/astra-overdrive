# 斬り上げの炎を作り直した（2026-09-13、3回目）

ユーザー指摘：「全然違うね。攻撃範囲と簡単なモーションは実装できたみたいだけど、再現度が
足りません。忠実に参考資料を見てから実行してね。」ゲームの録画も添付された。

**指摘は正しかった。** 前の版は炎が**滑らかな風船**で、16コマ（0.53秒）ほぼ同じ形のまま
キャラの横に居座っていた。参考はぼろぼろに裂けた本物の炎だった。

## 1. 何を見落としていたか

前回はスクリーンショットの11コマ列（476x71）から測っていた。**これが間違いだった。**
あれは縮小・再サンプルされた画像で、炎の内部構造が読めない。参考GIF（120x208、88コマ）を
直接測ると全く違う数値が出た。

録画から自分の動きを抜き出して（OpenCVで30fpsの全フレームを走査し、暖色の画素数が最大の
瞬間を探した）並べたところ、差は一目で分かった。

### GIFから測った数値

同じ物差し（全暖色画素の主軸、体の高さで正規化）を参考と自分の両方に当てた。

| | 参考 | 前の版 |
|---|---|---|
| 垂直からの角度 | 41.5° | 15.5° |
| 軸方向の長さ | 体1.91個分 | 2.52 |
| 軸と直交する幅 | 0.82 | 1.14 |
| **充填率** | **0.28** | **0.43** |

**充填率が決定的だった。** 参考の炎は自分の外接矩形の**2割から3割しか埋めていない**。
残りは隙間と筋と飛んだ火の粉だ。入れ子の輪郭を重ねる描き方では必ず9割埋まる。

さらに、GIFの暖色画素数は 2085, 2061, 1554, 1718 と**8コマ周期で循環**している。
炎は形を保たず、絶えず組み直されている。

色はGIFのインデックスカラーそのままで、**暖色9段の階段**で中間のグラデーションが無い。
`#f0f0f0` `#f8f8b8` `#f8d828` `#e8c838` `#f88818` `#f05818` `#f01000` `#c81810` `#981810`。

温度は**斜めに走る**。白は先端かつ前縁側、深い赤は根元かつ後縁側。同心の輪ではない。

なお、参考の体にある大きな黄色い塊は**刃でも装甲でもなく髪**だった。参考には刃が描かれて
いない。前回「刃を足すべきか」と考えたのは読み違いだった。

## 2. どう作り直したか

### 図形ではなく炎として組む
入れ子の輪郭を捨て、**隙間のある舌（lick）を層に重ねる**方式にした。冷たい層から順に敷き、
熱い層ほど先端側・前縁側へ寄せる。形は固定ハッシュから毎秒数回組み直すので、60fpsで
ちらつかずに churn する（乱数を毎描画で引くと毎フレーム別形になって激しく点滅する）。

### 円錐ではなく彗星
最初は手元から広がる円錐で組んだ。**寸法と充填率を参考に合わせても楔にしか見えなかった。**
手元から放射する舌の集合は境界が滑らかな弧になるので、舌を尖らせても棍棒にしても楔になる。

参考の炎は**彗星**だった。軸の6割ほどの位置に**でこぼこした頭**があり、そこから手元へ
**細まる首**が伸びる。頭は中心から全方向へ放射する舌の集まりで、これが境界をでこぼこに
する。首は冷たい層だけが持ち、白は頭にしかない（白を手元まで伸ばすと光線に見えた）。

### 途中で踏んだ間違い
- **ずらす量を帯自身の幅で掛けていた。** 熱い層は細いので、14px動かすつもりが2pxしか
  動かず、白が中央に残って輪になった。全体の幅を基準に直した
- **舌ごとに先端を前縁側へ曲げていた。** これと全体の傾きで舌が軸から15度ずれ、軸を41度に
  設定しても塊は19度に測れた。曲がりを後縁側へ反転した
- **キャンバスの角度の符号を取り違えた。** 垂直から離すには絶対値を小さくする側だが、
  一度逆に動かした
- **首を細くしすぎて3本の筋に分離した。** 幅を戻し、2本にして縁を崩した

### 合わせた結果

| | 参考 | 現在 |
|---|---|---|
| 垂直からの角度 | 41.5° | 36.9° |
| 軸方向の長さ | 1.91 | 1.66 |
| 幅 | 0.82 | 0.74 |
| 充填率 | 0.28 | 0.29 |

比較図は `qa/rising-ref/fire-compare.png`（上段が参考GIF、下段がゲーム、体の高さを揃えた
もの）。実寸のゲーム画面は `qa/rising-ref/in-game.png`。

## 3. まだ合っていないもの

1. **首の質感。** 参考の首は筋と穴が多い。こちらは円錐が2本重なった形で、縁は崩れている
   が内部が均一
2. **頭の粒。** 参考の膨らみは不規則。こちらは舌が放射状に等間隔なので、よく見ると
   規則的な花びらに見える
3. **長さが参考の87%**（1.66対1.91）。頭をこれ以上外へ出すと手元から離れて見える
4. **角度が5度浅い**（36.9対41.5）。塊の主軸は構築軸に弱くしか追随しないので、構築軸を
   これ以上寝かせても塊はあまり動かない
5. **絵そのもの。** 参考のスプライトは使っていない

## 4. テスト

`npm test` 112件合格（4件追加）。追加したのは、炎が図形に戻らないよう性質を固定するため。

- **冷→熱の9段で、輝度が単調に上がり、熱い層ほど小さいこと**
- **温度が斜めに走ること。** 熱い層の頭が先端側かつ前縁側にあることを確かめる。
  入れ子の輪郭なら全層が同じ中心に乗るので、この2つが等しくないことも見る
- **燃えながら形が組み直されること。** 8段の周期で全段が別形になり、かつ同じ段は
  常に同じ形であること（毎描画の乱数だと60fpsで点滅する）
- **噴出であること。** 刃の実長が60px以上で、垂直から28〜58度に寝ていること

browser-smoke 17項目・browser-mouse 12項目・saber-reach・release-check 合格。
弧は触っていない（89px、頂点0.58秒、着地1.00秒、4回噛む）。

## 5. 調整するには

- 炎の層・色・頭の位置・首の幅 → `assets/saber-rig.js` の `FIRE` 表
- 舌の形 → 同 `drawPlume()` の `lick()`
- 組み直しの速さ → 同 `churn`（`p.t*34` の係数）
- 炎の長さ・太さ・寿命 → 同 `plume()`
- 炎の向き → `keys[3]` の `angle` の列

# 追記：手法を変えた（同日、指摘2回目）

ユーザーが比較図を見て「この時点で違いに気づいてくれるかな？」。気づいた点は3つだった。

1. **首が無い。** 参考の炎は肩の横から既に幅の半分近くあり、そのまま雲のように膨らむ。
   こちらは手元から細い三角形が伸びて先に小さな花が付いていた。**あの細い首は私が
   作ったもので、参考のどのコマにも無い**
2. **色の割合が逆。** 参考は白と黄が主で赤は縁だけ
3. **頭が全体ではなく先端の飾りになっていた**

数値でも出た。幅の推移（根元から先端へ、最大幅に対する比）：

| | 根元 | 3分の1 | 中央 | 3分の2 |
|---|---|---|---|---|
| 参考 | 0.38 | 0.71 | 0.89 | 0.81 |
| その時点 | 0.30 | 0.62 | 0.74 | 0.98 |

色の割合：白・クリーム 31.4%対8.6%、赤 3.4%対**27.6%**、熱い側 68.3%対35.4%。

## 何が本当の原因だったか

首と色を直し、円錐から彗星へ、さらに実体を短く太く、と9回組み直した。**測った数値は
すべて参考に乗った**（角度39対41、幅0.84対0.82、充填率0.27対0.28）。それでも絵は
同心の楕円に戻り続けた。

**手法が違っていた。** 参考は手描きのドット絵ラスターで、硬い1pxの色段、斑な内部、
貫通した穴、ぼろぼろの縁がある。滑らかな塗り図形を何枚重ねても、必ず同心の帯と
均一な内部になる。数値をいくら合わせても届かない。

充填率0.28の読み方も間違っていた。**斜めの細長い形は、完全に詰まっていても外接矩形の
3割前後しか埋めない。** 隙間だらけに描く根拠ではなかった。しかも冷たい層を下に大きく
敷いているので、上の層の隙間から必ず赤が透けた。赤が何をしても8倍多かったのはこれだ。

## 変えた手法

炎を**ピクセル場として焼く**ようにした。小さなオフスクリーンに1ゲームピクセルずつ、

- 温度＝先端と前縁で高く、根元と後縁で低い斜めの勾配
- ×2オクターブの値ノイズ（粗い格子で斑、細かい格子で縁を裂く）
- 閾値以下は**描かない**（これが縁の裂けと穴になる）
- 残りをGIFの9色に量子化

churn の段が変わったときだけ焼き直し（技1回で8回）、平滑化を切って貼る。

結果：角度38.9（参考41.5）、長さ1.54（1.91）、幅0.89（0.82）、充填率0.36（0.28）、
熱い側62.5%（68.3%）、赤10.9%（3.4%）、白18.7%（31.4%）。

穴の量は参考より少なくしてある。ゲームの実寸だと多すぎると工場の背景が透けて
斑点に見え、炎に見えなくなるため。

## テストも作り直した

`npm test` 115件合格。炎のテストは**実際の色の割合を数える**ようにした。熱の計算を
`fireHeat` として関数に出し、テスト側で場を走査して9色に分類し、割合を確かめる。
閾値の位置を代理で見るのをやめた。加えて、**炎の内部に穴が空いていること**（縁から
離れた内側でも一定割合の格子が欠けていること）と、**ノイズが粗い格子で滑らかなこと**
（1pxごとのハッシュだと静止ノイズになる）を固定した。

# 追記：測り方そのものを直した（2026-09-13、「どうかな？」への対応）

ユーザーの「どうかな？」を受けて、公開版を実測と比較図で見直した。**寸法や角度は合っていても、
形がなめらかな木の葉のままだった。** 詰めていく途中で、それまでの計測が3つの点で間違っていた
ことが分かり、測り方から直した。

## 1. 間違っていた測り方

### 当てはめた軸で測っていた
炎の縁を、炎の塊に当てはめた主軸に沿って切って測っていた。**左右非対称な炎は当てはめた軸そのものを
回してしまう**ので、スライスが斜めに切れ、手元が太く先端が細いと読めた。炎自身の軸に沿って測ると
逆だった。比率での修正はこの読み違いを追いかけていた。今は参考を41.5度、こちらを各コマの炎の角度で
固定して測る（`qa/rising-fire-edges.py`）。

### 主人公の色を炎として数えていた
「暖色の画素」を炎とみなしていたので、参考の主人公（ゼロ）の**赤い装甲と金色の髪**が炎に混ざっていた。
このせいで、参考の下の縁に「3分の1の位置の膨らみ」があるように見え、それに合わせて作っていた。
**参考にそんな膨らみは無い。**

分け方を変えた。**主人公が立っているだけのコマ（6コマ目）に出てくる色を主人公の色、上昇中のコマに
出てきて立ちコマには無い色を炎の色**とした。主人公15色、炎16色で、**共通する色は0**。完全に分かれる
（`qa/rising-fire-clean.py`）。

### パレットの3色が主人公の色だった
以前GIFの暖色から抜き出した9色のうち、**3色は主人公のものだった。**

| 以前の色 | 正体 | 炎の本当の色 |
|---|---|---|
| `#f0f0f0` | 主人公の白い装甲 | `#f8f0f8` ラベンダーがかった白。炎全体の24.8%で最も多い色 |
| `#e8c838` | 主人公の金色の髪 | `#f8f040` 明るい黄 |
| `#f01000` | 主人公の赤い装甲 | `#e82810` 赤 |

炎の本当の最も熱い色は一度も拾えていなかった。それまでの「参考の白の割合」の数字はすべて誤りだった。

## 2. 正しく測って分かったこと

- **参考の炎は手元が暗い赤。** 最初の5分の1は赤と暗い赤で68%。こちらは黄色から始まり、暗い赤は0%
  だった。暗い赤は温度0からの範囲に割り当てていたのに、それより高い温度で画素を消していたので、
  **一度も描かれない色になっていた**
- **下の縁は手元がいちばん広い。** 手の下に暗い赤の炎が垂れているため。そこから先へ細くなる
- **上の縁は手元で細く、5分の1ほどでほぼ全幅**になり、先へゆるやかに細まる
- 全体の明るさ別の割合（白/黄/橙/赤/暗い赤）は参考が 40/17/23/12/8

## 3. 直したこと

1. **本当の炎の9色**に差し替えた
2. **温度の数値を1か所の表（`FIRE_HEAT`）にまとめて書き出し**、探索スクリプトで参考の色の配置
   （長さ5区分ごと、先端側の前縁・後縁ごと）に当てはめた。色の境目は炎自身の温度の分位点に置き、
   9色がそれぞれ参考どおりの割合を占めるようにした
3. **温度で輪郭を決めるのをやめた。** 冷たい画素を消していたので、色を当てはめるたびに輪郭が動き、
   手の下の暗い赤はどれだけ縁の表を広げても消されていた。**冷たい画素は消さずに暗い赤で描く**
   ようにし、輪郭は縁の表と裂けだけで決まる。これで初めて手元の下の縁が広がり、炎の根元が下がった
4. 縁の表を炎自身の軸での実測に合わせて2回当てはめ直した
5. 当てはめで**質感が消えた**。点数に質感を守る項目が無く、ノイズの揺れ幅が0.12まで落ちて、
   まだら模様が滑らかな縞になった。以降は0.28以上に固定（現在0.436）
6. **小さな炎が白くなった。** 温度の傾きは炎自身の長さに沿うので、振りかぶりの三日月・床を薙ぐ炎・
   落下中に構える刃のような短い炎は、根元から先端までの全段階が数ピクセルに詰まって熱くなる。
   炎の大きさ（全長85pxに対する長さの平方根）で傾きを弱めた。大きな炎は1のままで色は動かない
7. **白い芯に穴が点々と見えた。** 実寸では工場の暗い背景が透けて汚れに見える。参考の穴は冷たい
   部分にある。穴はクリーム色より冷たい画素にだけ開ける

## 4. 結果

|---|---|---|---|
| 最初の5分の1の赤＋暗い赤 | 68% | 7% | 70% |
| 全体 白/黄/橙/赤/暗い赤 | 40/17/23/12/8 | 40/33/23/4/0 | 43/15/19/13/9 |
| 下の縁、手元の2区分 | 0.67 / 0.64 | 0.35 / 0.54 | 0.56 / 0.61 |
| 上の縁、2区分目 | 0.47 | 0.29 | 0.38 |
| 炎の根元の高さ（足元から） | 0.55 | 0.89 | 0.65 |

縁は炎自身の軸で測って、上の縁は2〜10区分、下の縁は2〜9区分がおおむね1割前後で参考に一致する。
比較図は `qa/rising-ref/fire-compare.png`、11コマは `qa/rising-ref/sheet-compare.png`、実寸は
`qa/rising-ref/in-game.png`。

## 5. まだ合っていないもの

1. **先端が白すぎる**（最後の5分の1が白77%、参考61%）。先端の橙が足りない（7%、参考21%）
2. **全体の形。** こちらは長い斜めの帯で、参考は丸く閉じた塊に近い
3. 下の縁が先端の少し手前で閉じる
4. 実寸で黄色の部分にまだ穴の点が少し見える
5. **落下中の刃（9〜11コマ目）は読み違いの可能性がある。** 参考の頭上の黄色い形は、刃ではなく
   主人公の髪かもしれない。体の黄色い塊が髪だったのと同じ見落としの疑いがある。未確認

## 6. テストと道具

`npm test` 116件合格、モーション37件合格。炎のテストを正しい測り方に合わせて書き直した。

- パレットが本当の炎の9色であること
- **手元が赤く先端が白いこと**を明るさの帯で数える（全体の割合、最初の5分の1の赤、先の白）。
  暗い赤が実際に出ること

- 色の配置 → `assets/saber-rig.js` の `FIRE_HEAT` と `FIRE` の閾値 `s`
