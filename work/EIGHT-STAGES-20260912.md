## 2. 新ステージの性格

ステージの作りを、そこで待つボスの手札に合わせた。

- **CINDER FLATS**（ASHMAW：曲射と地雷）
  見通しのいい平地。登りは2段までしかなく、長く居座れる高所が無い。
  降ってくる攻撃から逃げ続ける区画。
- **ANVIL DEPTH**（GRAVELOCK：最重量、跳んで潰す）
  砲座が14門並ぶ坑道。3段の登りが各所にあり、上から砲座を潰して進む。
- **VOID CHOIR**（NULLPRIEST：手数で押す）
  4段の高い登りが9箇所。ドローン18体が上層に居る。弾幕に慣れさせる縦の区画。
- **FILAMENT RUN**（SPARKWIDOW：最速）
  足場の幅が90pxしかない細い区画。歩行兵が多く、止まると囲まれる。
- **CROWN VAULT**（OBSIDIAN CROWN：8手すべて）
  最長11200px、足場67枚、敵41体。高い登りと低い疾走が交互に来る。

### 難易度の並び
ボスの脅威度を「装甲÷テンポ」で見ると 72 / 80 / 101 / 77 / 93 / 106 / 123 / 165 になる。
3→4 でいったん下がる。ASHMAW は装甲88でもテンポ1.15と遅く、単体では中位のためだ。
ここはステージ側の作り（高所の無い平地）で補っている。4以降は単調に上がる。

## 3. 作り方の担保

足場を置く `stair(add, x, [高さ…], 幅)` を追加した。190px間隔で並べ、隣り合う段の高さの差が
ジャンプの84px以内であることを前提にしているので、**この形で置いた登りは構造的に必ず到達できる**。
手で1枚ずつ検算する必要がなくなった。

穴は149pxを超えたら必ず中継足場を置く規則のまま。全ステージで満たしている。

## 4. 検証

`qa/stage-audit.cjs` が9ステージすべてを回して合格。確認しているのは、穴の跨ぎ、足場の到達、
敵の接地、歩行兵の往復範囲、アイテムの到達、チェックポイントの接地と前進、セクターの切れ目、
開始地点からボスゲートまでの跳躍到達可能性、そしてロスターの8体が全員どこかから到達できること。

初回実行で3件の配置ミスを検出して直した。

1. FILAMENT RUN の回復が足場の端から30px外に落ちていた
2. FILAMENT RUN のチェックポイント1つが床の無い穴の上にあった
3. CROWN VAULT の回復が2枚の足場の間に落ちていた

`qa/stage-playthrough.cjs` を実ブラウザで9ステージ通した。各ステージが選択画面から起動し、
全長のセクター表示が動き、アリーナでボスが所持技をすべて使い、倒すと勝利へ行き、
選択画面に記録が載り、リロード後も残ることを確認した。BOSS RUSH の8体連戦も完走する。

`npm test` 全89項目合格。公開用ビルド（29ファイル 8.15MB）でも release-check 合格。
選択画面はキーボードで9番目まで届き、その行が画面内に入ることも確認した（横向きスマホでも）。

図は `qa/stage-map-<id>.png`。新設5ステージをまとめたものが `qa/stage-maps-new.png`。

### ステージ選択に出した
240pxの正方形に収めて（切らずに全身が入る形で）各ミッション行に並べた。
**背景は意図的に残している。** 枠の中に収まると資料写真として読めるからだ。
8枚あわせて165KB。`tools/make-boss-portraits.py` で作り直せる。

### 戦闘中のスプライトにも入れた
元絵は透過ではなく工場の情景が描き込まれているので、そのままでは四角い絵が乗ってしまう。
`tools/cut-boss.py` を書いて GrabCut で抜いた（初回＋再シードして2回、計3パス）。

原寸で見ると **tidebreaker / coilhead / gravelock / sparkwidow は抜き残しがある**。
機体も背景もどちらも暗い青緑で、色の分布が重なっているためだ。いったんは採用を見送ったが、
**実際にゲームが描くサイズ（横130〜190px）で並べて確認したところ、残りはほぼ見えなかった。**
共通機体の色違いを8体並べるより明らかに良いので、7体すべてを採用した
（WARDEN は既存の透過素材がそのまま本人なので据え置き）。

- 出荷用は `assets/bosses/<id>.webp`。横380pxに落として7体で353KB
- `assets/bosses.js` の各エントリに `sprite` を追加。`look`（色フィルタ）は
  絵が読み込めなかったときの保険として残し、絵がある場合は適用しない
- renderer は絵の縦横比を保ったまま、当たり判定の体（w×h）に合わせて
  `min(w*1.5/絵幅, h*1.35/絵高)` で拡縮し、足元を体の底に合わせる

読み込みは非同期なので、届くまでの数フレームは従来の共通機体が出る。落ちることはない。

もっときれいに抜きたい場合は、背景を無地（透過が理想。真っ白やマゼンタでも可）にした元絵を
`assets/bosses/src/` に置いて `tools/cut-boss.py` を通し直せばよい。

## 5b. 当初の未処理メモ（解決済み）

**8枚の画像はチャットには届いているが、ディスク上のファイルとして見つけられなかった。**
Downloads、Pictures、Desktop、プロジェクト配下を探したが無い。画像の中身を直接ファイルへ
書き出す手段もこのセッションには無い。

そのため今のボスは、共通の機体画像に色フィルタをかけて描き分けたままになっている。

取り込む準備自体は済んでいる。`assets/bosses.js` の各エントリに `sprite` を足し、
renderer がそれを読む形にすれば差し替えられる。画像を次のどれかで渡してもらえれば作業できる。

- `assets/bosses/` を作ってそこへ8枚を保存する（名前は warden / tidebreaker / coilhead /
  ashmaw / nullpriest / gravelock / sparkwidow / obsidian-crown が分かりやすい）
- または保存場所を教えてもらう

透過PNGだと背景の抜きが不要で最もきれいに出る。背景付きでも、
既存のボス画像と同じように矩形で描くことはできる。
