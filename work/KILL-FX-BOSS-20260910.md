# 撃破演出・回復ドロップ・ボス6パターン（2026-09-10）

ユーザー依頼は3件。
1. 雑魚キャラを倒したときに爆発演出を入れる
2. 25% の確率で回復アイテムをドロップする
3. ボスモンスターに4〜6パターンの攻撃を持たせる

## 1. 撃破時の爆発

### 変更前
バスターで倒したときだけ `_burst()`（同じ粒子を12個＋リング1個）と `explode` 音が鳴り、
セイバーで倒したときは粒子も音も無かった。倒し方によって手応えが違っていた。

### 変更後
`NeonGame.prototype._killEnemy(e)` を新設し、バスター・セイバー両方の撃破をここに集約した。
`_bullets` と `_damageNearby` の中に直書きされていた `e.dead=true; s.kills++; s.score+=100;` は
すべてこの呼び出しに置き換えている。得点も撃破数もこれまでと同じ。

`_explode(x,y,color,power)` が実際の演出を作る。内訳は次の4層。

| 層 | 種類 | 内容 |
|---|---|---|
| 芯 | flash | 白い光。0.14秒で消えながら急速に広がる |
| 衝撃波 | ring | 敵色のリングと橙のリングの2本。0.30秒と0.44秒 |
| 破片 | spark | 14個。全方位＋やや上向き。重力560、空気抵抗あり |
| 煙 | smoke | 6個。上へ流れながら膨らむ |

色は敵の種類で変える。ドローンは桃、タレットは淡黄、ウォーカーは橙。
画面揺れ `s.shake` を 0.18 以上に、`explode` 音も鳴らす。

**低モーション設定**では煙を出さず、破片を7個に、外側のリングも省く。
粒子の総数上限は 180 → 240 に引き上げた。爆発1回で23個使うため。

粒子システム自体も拡張した。1粒子ごとに `gravity` / `drag` / `grow` を持てるようにして、
未指定なら従来どおり重力200・抵抗なし・サイズ固定で動く。既存の粒子の挙動は変わらない。
描画側は `flash` / `ring` / `smoke` / `spark` を描き分ける。

## 2. 回復アイテムのドロップ

`AstraCombat.dropChance = .25`、`AstraCombat.dropHeal = 1`。

撃破ごとに `_drop(e)` が判定する。乱数は `NeonGame.prototype._roll()` に切り出してあるので、
テストから差し替えられる。ボスはドロップしない（雑魚のみ）。

落ちたセルは初速 -110 で少し跳ね上がってから重力900で落下し、真下の足場の上に着地して止まる。
足場が無ければ画面下（y>430）で消滅する。穴の上で倒しても地面に浮いたまま残らない。

回復量は **1**。設置済みの回復パック（ステージに9個）は従来どおり **2** のまま。
`k.heal` が無ければ2として扱うので、既存の配置データは変更していない。
全28体を倒すと期待値7個、最大でも装甲上限8で頭打ちになる。数字を変えるなら
`combat.dropHeal` の1箇所だけ直せばよい。

見た目は設置パックの菱形と区別して、赤い四角に白十字の小さなセルにした。着地後は上下に軽く揺れる。

実測ドロップ率：ブラウザ実機で40周・1120体撃破して **25.4%**。

## 3. ボスの攻撃6パターン

### 変更前
3パターン（volley / wave / dash）の固定ループ。`_boss` の中に if/else で直書きされていた。

### 変更後
`AstraCombat.bossPatterns` の表と、`bossPool()` / `bossNext(current)` に分離した。

| パターン | 表示名 | 溜め | 実行 | 内容 |
|---|---|---|---|---|
| volley | VOLLEY | 0.95 | 1.6 | 5発の扇状射撃（従来どおり） |
| wave | GROUND WAVE | 0.90 | 1.7 | 床を這う大玉。威力2、半径9 |
| dash | CHARGE | 0.85 | 1.5 | 突進。0.9秒間260px/s |
| mortar | MORTAR | 1.00 | 1.5 | 曲射3発。プレイヤーの足元とその左右72pxへ落ちる |
| ring | SPREAD | 0.85 | 1.4 | 全方位10発。自機の輪郭の外から出る |
| slam | SLAM | 0.75 | 1.6 | 跳び上がってプレイヤーを追い、着地で左右へ衝撃波2発 |

**2026-09-11 追記**：当初は体力段階で解禁していく形（第1段階3種→第2段階5種→第3段階6種）
だったが、ユーザー指示で **最初から6種すべて使う** ように変更した。`bossPatterns` から `phase` を外し、
`bossPool()` は常に全6種を返す。プールは順番に巡回するので、一周見れば読める。
体力段階（66% / 33% 区切り）は溜め時間の倍率にだけ残っていて、×1 / ×0.82 / ×0.68 で短くなる。
つまり技の種類は最初から全開で、削るほど速くなる。

新しい弾の仕組みを2つ足した。
- `_spawn` の第8引数で任意のフィールドを弾に持たせられる（`g` 重力、`r` 半径、`kind` 見た目、`pops` 着弾消滅）
- `g` を持つ弾は落下し、`g` か `pops` を持つ弾は足場に当たると小さく爆ぜる（`_shellLands`）

迫撃の弾道は着地点が床面に一致するよう解いてある。滞空1.2秒、初速は
`(床Y - 銃口Y - g*T*T/2) / T`。平らな床なら中央弾は狙点から12px以内に落ちる。

### 予告表示
6種類あると何が来るか読めないと理不尽になるので、溜め中は攻撃ごとに違う警告を出す。

- volley: 腕から前方へ広がる破線3本
- wave: 床に沿って伸びる赤い破線
- dash: 前方の山形3つ
- mortar: プレイヤーの足元とその左右に照準リング3つ（プレイヤーを追う）
- ring: ボスを囲む破線の円（脈動する）
- slam: 頭上の上向き矢印＋着地予定地の破線枠

体力ゲージの右端に技名も出す。溜め中は琥珀色に「▸ MORTAR」、発動中は灰色で技名のみ。
すべての攻撃は必ず溜めを挟む。最短でも 0.51秒（slam の第3段階）ある。

## 検証

`tests/fx-drops-boss.test.cjs` を新規追加（13項目）して `npm test` に組み込んだ。

- どちらの武器で倒しても爆発の4層が揃い、音と揺れが出る
- 低モーションでは煙が消え粒子が減る
- ドロップ判定の境界（0 / .249 / .25 / .9）と、4000回の実測が25%±3%
- 落下したセルが真下の面に着地して止まる／穴では消える
- 回復量がドロップ1・設置2で、装甲上限を超えない
- プールが常に6種を返し、巡回が全6種を一周してから先頭へ戻る
- 装甲満タン・半分・2割のいずれでも、60秒回すと6種すべて出る
- どの攻撃も溜めを挟み、29フレーム以上ある
- 各パターンの中身（扇の5発／床を這う大玉／突進距離／全方位10発）
- 迫撃弾が全弾着弾して消え、平床なら中央弾が狙点12px以内
- slam が離陸し、着地で左右へ衝撃波を出し、画面が揺れる
- slam 中もアリーナ境界を出ない

`npm test` 全70項目合格。

ブラウザ実機検証：
- `tests/browser-smoke.cjs` 16項目合格、例外なし
- `tests/browser-mouse.cjs` 12項目合格、例外なし
- 20秒のボス戦を回して6パターンすべてが出ることを確認、JSエラーなし

図：`qa/boss-patterns.png`（6パターンの溜めと発動）、`qa/kill-fx.png`（爆発の1フレームごと）。
再現スクリプトは `qa/boss-patterns.cjs` と `qa/kill-fx.cjs`。

## 途中で直した既存の不具合（今回の変更とは無関係）

1. `tests/browser-smoke.cjs` がボス出現位置を 4750 と直書きしていた。ステージ拡張で
   アリーナが 9020 へ移ったあと、この行以降がずっとタイムアウトしていた。
   `AstraCombat.arena.spawn` を読むよう修正。あわせてボス撃破の手順が
   「Jを押しっぱなし」だったのを、押して離す繰り返しに直した（押しっぱなしではチャージが
   溜まるだけで弾は出ない）。溜め中の攻撃で結果がぶれないよう、この工程だけ `boss.timer` を止める。
2. `tests/browser-mouse.cjs` が右クリック後100msで判定していた。刃の軌跡に合わせて
   1段目の命中を0.16秒へ動かした結果、間に合わなくなっていた。命中を待つ方式に変更。
