# プレイヤーの絵柄を1系統に統一 — 2026-09-10

## 依頼
「絵柄変わってない？どれか一つに絞りましょう」。統一先はユーザー選択で**関節リグ**。

## 統一前の状況
10状態が3系統の素材に分かれていた。

| 素材 | 使われていた状態 |
|---|---|
| `assets/player-idle-v2.png` 一枚絵 | 静止のみ |
| `assets/player-run-v4.svg` 関節リグ | 走行、セイバー3段 |
| `assets/player-sheet.png` 旧シート | チャージ、発射、ジャンプ、落下、ダッシュ、壁張り付き |

10状態のうち6状態が一番古いシートのままだった。

## 実装

### リグに不足していた姿勢を追加（assets/run-rig-v6.js）
- `airPose(phase, rise)`：ジャンプと落下。`rise` は +1で上昇、-1で落下。前脚の膝を上げ、後ろ脚を流す。
  上昇時ほど強く畳む。
- `dashPose(phase)`：前傾を深くし、前脚を伸ばして後ろ脚を浮かせる。
- `wallPose(phase)`：壁側へ寄せ、後ろ脚の膝を上げる。
- `upperPose(phase, mode)` を真偽値から状態名に変更。air/dash/wall それぞれの前傾と体の振りを持つ。
- `poseFor(mode, phase, rise)` で状態名から姿勢を引く。`draw()` は `o.mode` を見る。

いずれも「奥側＝キャラ左脚が前」という既存の取り決めに合わせてある。

### 静止をリグに戻した
`draw()` は一枚絵へ分岐しなくなった。分岐は `o.spriteIdle` を渡したときだけ残してあるので、
`assets/player-idle-v2.png` と描画コードは失われていない。戻したくなればフラグ1つで戻せる。

戻すにあたり、`standingPose()` と待機時の `armPose()` を、以前ユーザーが承認した形へ戻した。
一枚絵に切り替えた際のフォールバックは、腰を左右に割って足を±12まで開く姿勢に書き換えられていたが、
これは以前「かっこ悪すぎ」と却下された合成リグの見た目に近い。骨盤を1点にして足を±8、
奥側の脚を前に出す承認済みの立ち姿に戻した。

### 描画と弾の経路（render.js、game.js）
- `combat.rigMode(p)` を追加。saber / wall / dash / air / run / idle を返す唯一の判定。
- `combat.rigPhase(p)`、`combat.rigRise(p)` を追加。`rigRise` は上昇で+1、落下で-1に正規化する。
- `render.js` は `rigMode` が saber 以外なら、必ずリグで描く。
- `combat.muzzle(p)` も saber 以外は必ずリグの砲口を返す。チャージ中・発射中も同じ立ち姿から出る。

`idlePose()` と `runPose()` は他の呼び出し元のために残してある。

ゲーム本体に問い合わせて確認する。

## 検証
- `npm test` 全57項目合格。
- 旧挙動を前提にしていたテストを書き換えた。
  - 待機の立ち姿：骨盤が1点であること、奥側の脚が前・手前が後ろであること、呼吸で足裏が浮かないこと。
  - 全状態が1つのリグ姿勢に解決されること。チャージ中・発射中も idle のままであること。
  - 砲口：全姿勢でリグの砲口と一致すること。旧スプライトのアンカー表は廃止。
  - チャージ時は砲口が上がり、向いている方向へ伸びること。
- `qa/silhouette.cjs` を統一後の基準へ書き換え。idle/run/air/dash/wall の背丈が揃い、
  面積比が待機比1.18倍未満であることを確認する。
- `qa/idle-redrawn-verify.cjs` は `spriteIdle` 経路を検証するように変更。一枚絵が今も正しく描けることを守る。
- `qa/build-live.cjs`：実ゲームで走行中に撃ち、弾と砲口が誤差0で一致。
- 606姿勢、セイバー3段の幾何、多段ヒット合計20.25も合格。
- 画像：`qa/all-states.png`（12姿勢）、`qa/unified/live-states.png`（実ゲーム7状態）。
