# ボス8体とボスラッシュ（2026-09-11）

ユーザー依頼：「ボスキャラを合計8体用意して」

結果：ボスは8体になった。ステージ1〜3にそれぞれ別の1体、4つ目の BOSS RUSH で8体すべてと連戦できる。

## 1. ボスもデータに切り出した

`assets/bosses.js` に `AstraBosses` を新設。1体＝1エントリで、次を持つ。

| 項目 | 効くところ |
|---|---|
| name / title / jp / blurb | 体力ゲージとステージ選択の表示 |
| hp / easyHp | 装甲（難易度別） |
| w / h | 当たり判定の体。描画もこれに追従して拡縮する |
| look | 共通の機体画像にかけるフィルタ。色で見分けがつく |
| pool | 所持技と、その巡回順 |
| tempo | 溜め時間の倍率。1未満で速く、超で遅い |
| knobs | 技ごとの数値。既定値に上書きされる |

ステージ側は `bosses: ['warden']` のように id で指名する。エンジンは体力も体格も色も技も、
すべてここから読む。ボスを足す作業は、この配列に1項目足すだけになる。

### 壊していないことの担保
切り出しの前に、今の WARDEN が6技それぞれで撃つ弾（座標・速度・半径・威力・種別）と、
突進時間・跳躍初速・タイマーを `tests/warden-baseline.json` に凍結した
（`tools/snapshot-warden.cjs` で再生成）。切り出し後、**6技すべてが1発ずつ完全一致**することを
`tests/bosses.test.cjs` で常設検証している。WARDEN の手触りは変わっていない。

## 3. 技を8種に増やした

既存6種に2つ足した。

- **mines（地雷）**：曲射で投げ、落ちた場所に留まって導火線が尽きると上向きの扇を撒く。
  床が安全でなくなる。
- **wall（弾幕の壁）**：縦に並んだ弾が1枚だけ欠けた状態で飛んでくる。穴を探して抜ける。

技の数値はすべてボスのエントリから読むようにした。同じ `ring` でも WARDEN は10発、
NULLPRIEST は14発になる。`volley` の弾数・速度・散り、`wave` の本数・速度・大きさ、
`dash` の速度と時間、`mortar` の発数と散り、`slam` の跳躍・追尾・衝撃波、
`mines` の数と導火線、`wall` の段数と速度が、それぞれ独立している。

予告表示も2種追加した。地雷は着弾予定地に四角、壁は前方に縦線。

## 4. BOSS RUSH（ステージ4）

道中の無いアリーナだけのステージ。8体を順番に相手にする。1体倒すごとに装甲が2だけ戻る。
全長1950px、床は1枚。避けるための足場が8枚ある。

エンジン側は、ボスが落ちきったときに次がいれば補充し、いなければ勝利へ渡す形にした。
既存のステージは `bosses` が1体なので、従来どおり倒した時点で勝利になる。

ステージ選択の各行に「BOSS // 名前」を出すようにした。BOSS RUSH は「BOSS // 8 FRAMES」。

## 5. 検証

`tests/bosses.test.cjs` を新規追加（8項目）して `npm test` に組み込んだ。

- 8体いて、id も名前も重複せず、選択画面に出せる項目が揃っている
- どの2体も、技構成・テンポ・数値・見た目のいずれかで必ず違う。装甲は最小の1.6倍以上に開く
- **WARDEN が凍結した基準と1発単位で一致する**
- 各ボスが所持する技すべてで、実際に何かが起きる
- 壁は1段だけ欠けた縦列になる。地雷は弧を描き、着地点に留まり、導火線が尽きて扇を撒く
- エントリの数値が実際に技へ届いている（NULLPRIEST の ring は WARDEN より多い、など）
- ボスラッシュが8体を順番に送り込み、間に装甲を2戻し、最後で勝利になる
- 単体ボスのステージは従来どおり1体倒せば勝利になる

`qa/stage-audit.cjs` に「ロスターの全員がどこかのステージから到達できる」検証を足した。
`qa/stage-playthrough.cjs` は実ブラウザで、各ステージのボスが所持技をすべて使うこと、
ボスラッシュが8体を順番に出して倒し切れることを確認する。公開用ビルドでも合格。

`npm test` 全89項目合格。browser-smoke 17項目、browser-mouse 12項目合格。

図：`qa/boss-roster.png`（8体を溜め動作の瞬間で並べたもの）。再現は `node qa/boss-roster.cjs`。

## 7. 断っておくこと

**機体の絵は共通で、色と大きさで描き分けている。** このセッションには画像生成の手段が無く、
8体分の新規スプライトは用意できない。形そのものを変えたい場合は、Astra 側の画像生成が必要になる。
差し替えは `assets/bosses.js` の1行（`look`）を画像指定に変える程度の作業で済むよう、
描画は体格と色をエントリから読む形にしてある。
