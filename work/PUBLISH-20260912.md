# Web に公開した（2026-09-12）

ユーザー依頼：「YouTube Playables に登録申請するために公開URLが必要みたいだ。現段階までの
制作物を一度Webで誰でもアクセスできるように公開してくれるかい？」

結果：Artifact として公開した。**ただし既定では非公開で、誰でも見られる状態にする操作は
ユーザー側で1回必要。** そこだけはこちらから設定できない。

## 1. 公開先

    https://claude.ai/code/artifact/41a2935d-61a1-44d6-b160-f0acf4a237fd

中身は `release/` の44ファイルそのもの。ページ本体 + 43個の付随ファイルで、
ビルドしたバンドルと1バイトも違わない。

### 誰でも見られるようにする手順
上のURLを開き、ページの共有メニューから「リンクを知っている全員」に変更する。
**この操作をするまでは、サインインしていない人には「Sign in to view this page」が出る。**
実際にこの状態を確認済み。

### 申請に使えるかどうか
共有した Artifact のURLが Claude のアカウント無しで開けるかどうかは、こちらでは確認できない。
確認するにはサインイン済みのブラウザーが要るが、この環境には繋がっていない。
**審査に出す前に、シークレットウィンドウで自分でURLを開いて確かめてほしい。**

開けなかった場合、あるいは公式の申請にはもっと素直なURLが欲しい場合は、静的ホスティングが確実。
`dist/ASTRA-OVERDRIVE-web.zip`（8.38MB）をそのまま置くだけで動く。

- **Netlify Drop**（app.netlify.com/drop）ZIPをドラッグするだけ。アカウント不要でURLが出る
- **itch.io** HTML5ゲームとしてZIPをアップロード。ゲーム向けなので体裁も合う
- **GitHub Pages** リポジトリを作って `release/` を push し、Pages を有効化

どれもアカウントのサインインが要るので、こちらでは代行しない。

## 2. 公開のために足したもの

### `tools/make-artifact-page.cjs`
Artifact は `<!doctype>` `<html>` `<head>` `<body>` を自前で用意して、渡したファイルを
body の中に描く。そこで `release/index.html` から文書の外枠を剥がし、タイトル・
スタイルシートの読み込み・マークアップ・スクリプトだけを残したページを
`dist/artifact-page.html` に書き出す。付随ファイルは無加工で隣に並ぶので、
**ページは実バンドルと同じ相対パスのまま**動く。

実ホスト向けにしか意味の無い head タグ（OGPカード、manifest、アイコン）は落としている。
Artifact は自前のカードとアイコンを持つため。

書き出す前に、外部サイトを参照していないこと、要求するファイルがすべてバンドルに
入っていることを確認する。ビルド本体と同じ規則。

### `qa/artifact-page.cjs`
**公開するページそのものを、Artifact が被せるのと同じ骨組みに入れて実際に遊ぶ。**
確認するのは、ゲーム自身の背景がホストの白地を上書きしていること、タイトル絵が出ること、
メニューが4項目出ること、ミッションが9枚と地図が出てボスの顔8枚が全部読めていること、
実際に走って前進すること、404が無いこと、例外が無いこと、そして4.98MBのBGMが
`audio/mpeg` で届くこと。

実行結果：全項目合格、404ゼロ、例外ゼロ。

**これで確認できないこと**：Artifact ホスト側の内容制限が各ファイルをどう扱うか。
それは公開URLをサインイン済みの人が開かないと分からない。

## 3. ついでに直したもの

フルスタート要求が拒否されたときの未処理の例外を止めた。
`document.documentElement.requestFullscreen()` は iframe の中では拒否されることがあり、
返ってきた Promise を誰も受けていなかった。**Playables 自体がゲームを iframe で動かす**ので、
Artifact のためだけでなく本番でも効く修正。変更は `ui.js` の1行。

## 4. 検証

`npm test` 全93項目合格。`qa/release-check.cjs` 合格。`tests/browser-smoke.cjs` 17項目合格。
`qa/artifact-page.cjs` 合格。公開用ビルドは44ファイル 8.67MB、zip 8.38MB で変わらず。

Playables の技術要件は4つとも満たしたまま。ZIP1個の自己完結、外部通信ゼロ、
初回30MB以内（音楽を除いて3.93MB）、モバイル対応。

## 5. GitHub Pages へ（2026-09-12 追記）

ユーザーが GitHub のアカウントを持っていると分かったので、そちらへ移す準備をした。
**Pages のURLはログイン不要で誰でも開ける普通のURLで、申請に出すならこちらが確実。**
公開範囲は「ソース一式を公開リポジトリ」、リポジトリ名は `astra-overdrive` をユーザーが選択。

### 手元で済ませたこと

- `.gitignore` を直した。`dist/` が入っておらず、**このままだとバックアップZIP 77個・1.8GBを
  丸ごとコミットするところだった。** `qa/` は丸ごと除外されていたが、3.9GBの撮って出しを
  除外しつつ検証スクリプト（`qa/*.cjs` と `*.py`）は残す形に変えた。`test-out.txt` も除外
- 最初のコミットを作った。196ファイル 43.7MB、ブランチは `main`
- 中断された `git add` の残骸1.83GBが `.git/objects` に溜まっていたので、コミット後に
  `git gc --prune=now` で掃除した。1.84GB → 42.47MB
- `tools/build-release.cjs` に `--ci`（`npm run build:ci`）を足した。ビルドサーバーでは
  2つの手順が意味を持たない。**新しいクローンには意味のある更新時刻が無い**ので
  WebPの鮮度チェックは雑音を読むだけになるし、Pages はフォルダを配るのでZIPに固める
  必要が無い（PowerShell も要らなくなる）
- `.github/workflows/pages.yml` を追加。push でテストを通してからビルドし、`release/` だけを
  公開する。**リポジトリに置いたソースではなく、ビルドした成果物を配る**
- README の先頭に遊ぶリンクを足し、「ステージ3種」という古い記述を9種に直した

### 検証

コミット対象のファイルだけを別フォルダーへ写して `npm test` と `--ci` ビルドを実行し、
**196ファイルだけで全部揃うこと**を確認した。さらに全テキストをLFに変換して同じことを
実行した。CI は Linux で LF のファイルを受け取るため。どちらも全93項目合格、
出来上がるバンドルは44ファイル8.67MBで手元と同一。

### 残っている手順（アカウントが要るのでこちらでは代行しない）

1. github.com で空の公開リポジトリ `astra-overdrive` を作る（README等は付けない）
2. `git remote add origin` して push。Git Credential Manager が入っているので、
   初回はGitHub自身のサインイン画面が出る。こちらが認証情報を扱うことはない
3. Settings → Pages → Source を "GitHub Actions" にする

これで `https://<ID>.github.io/astra-overdrive/` が生える。
