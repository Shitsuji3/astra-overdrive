# 斬り上げを追加した（2026-09-12）

ユーザー依頼：参考画像を添えて「こんな感じの上に向かって切り上げるモーションを追加して。
↑+セイバーボタンで出るようにしてね。」

結果：セイバーの4つ目のモーションとして**斬り上げ**を足した。↑を押しながらセイバーで出る。
既存の3段コンボとは別扱いで、繋がらないし繋がらせない。

## 1. モーション

`assets/saber-rig.js` に4段目のキーフレームを足した。9キーで構成。

後ろ足に沈んで刃を低く後ろへ垂らし、膝で伸び上がりながら刃を床から一気に頭上まで運ぶ。
終わりは腕を頭上に伸ばし切った姿勢で、そこが一番届く。

残像も専用に描いた。既存の1・3段目は「上から下」へ回る弧なので、逆回りの弧を新しく足してある。
かかとの後ろから前方へ抜け、腰の高さを通って頭上まで。

刃の長さは53（1段目48、3段目57の間）。斬り上げは距離より高さが要るため。

## 2. 届く範囲

プレイヤーの体を基準にした実測。

| 技 | 頭上 | 足元 | 前方 | 後方 |
|---|---|---|---|---|
| 1段目 振り下ろし | 47px | 42px | 65px | -2px |
| 2段目 横薙ぎ | -6px | 19px | 53px | 26px |
| 3段目 締め | 61px | 42px | 72px | -2px |
| **斬り上げ** | **72px** | 31px | 55px | -9px |

**全技の中で最も高く、前方は最も短い。** 対空として成立する形になっている。
走りジャンプの高さが84pxなので、頭上72pxはジャンプの大半をカバーする。

威力は通常の一振りと同じ4.5。当たるのは振り始めから0.14秒（1段目は0.16秒）。
刃が床から出てくるぶん、わずかに遅い。

## 3. 操作

**↑ はジャンプではなくなった。** これは避けられない変更だった。↑がジャンプのままだと
↑+セイバーが必ずジャンプを伴い、地上からの対空として使えない。

- ジャンプ：Space / Z / ゲームパッドA / 画面の▲　（↑を外しただけで他は不変）
- 上：↑ / W / ゲームパッドの十字上・左スティック上 / 画面の↑
- 斬り上げ：上＋セイバー

画面上のパッドに「↑」を足して8個にした。360px幅の端末でも重ならずに収まることを確認済み。
タップでも斬り上げが出る。

操作ガイドの表も直した。

## 4. 繋がらない扱い

斬り上げは3段コンボの一部ではない。

- 斬り上げ中にセイバーを押しても次段は予約されない
- 斬り上げのあとはコンボが0に戻る
- 1段目・2段目の途中で↑を押しても、既に出ている振りは変わらない

「↑を押していたら必ず斬り上げ」という一本の規則で、状態に依存しない。

## 5. 検証

`npm test` 合格。追加したのは4項目。

- ↑＋セイバーで4段目が出て、セイバー単体では1段目が出ること。斬り上げが繋がらないこと
- **↑がもうジャンプしないこと**、Spaceは今までどおり跳ぶこと
- 斬り上げが振り下ろしより15px以上高く届き、前方は短いこと
- **振り下ろしでは届かない高さのドローンを斬り上げは落とせること。**
  ドローンは実測した2技の天井の間に置いており、刃の太さ7pxも勘定に入れている

既存の `motion-combo` のダメージ表テストに4段目を足した。

実ブラウザーで、844x390・390x844・360x640 の3サイズとも**8個のボタンが重ならずに収まり、
↑を押しながらセイバーをタップすると斬り上げが出る**ことを確認。例外0。
browser-smoke 17項目・browser-mouse 12項目・release-check・9ステージ通し合格。

コマ送りの比較図は `qa/saber-rise.png`。上段が斬り上げ、下段が既存の振り下ろし。

## 6. 調整するには

- 高さ・弧の形 → `assets/saber-rig.js` の `keys[3]`（9キー）

## 7. 出ないと言われた（2026-09-12 追記）

ユーザーから「でないぞ？」。調べた結果、**コードは公開サイトで正しく動いていた。**
4つの入力経路（K単体 / ↑+K / 右クリック単体 / ↑+右クリック）を本番URLで自動操作して、
それぞれ 1 / 4 / 1 / 4 段目が出ることと例外0件を確認済み。

原因として考えられるものを2つ潰した。

### 入力の受け口が固すぎた（直した）
斬り上げは「↑を押している瞬間にセイバーを押す」ことを要求していた。人間は2つのキーを
同じフレームで押せないので、数十msずれれば出ない。これが一番ありそうな原因。

`combat.risingGrace`（0.18秒）と `combat.risingConvert`（0.08秒）を足して、どちらの順番でも
拾うようにした。ジャンプが既に `jumpBuffer` で同じことをしている。

- **↑を離してから0.15秒以内にセイバー** → 斬り上げ。押しっぱなしなら当然出る
- **セイバーが先に入って3フレーム以内に↑** → 出かけた1段目を斬り上げに差し替える。
  刃が手を離れる前なので見た目に飛びは出ない
- それより古い入力は拾わない。振り始めた1段目は1段目のまま

実ブラウザーで「↑をタップして離し、70ms後にKを押す」という人間らしい入力で4段目が出ることを
確認した。

### ブラウザーのキャッシュ（説明した）
GitHub Pages は `Cache-Control: max-age=600` を返す。deploy 直前に開いていた場合、10分間は
古い `game.js` と `index.html` が使われる。**ローカル配信（`server.cjs`）は `no-cache` なので
こちらは無関係。**

見ている版を一目で判別する方法をユーザーに伝えた。ゲーム画面の下の操作表記の末尾が
`↑+K RISING` になっているかどうか。出ていなければ古い版を見ている。

### 検証
`npm test` 合格。追加1項目で、↑を離してから0フレーム後・5フレーム後のセイバーが斬り上げになり、
40フレーム後はならないこと、セイバーが先でも0〜3フレーム後の↑なら斬り上げになり、
20フレーム後はならないことを見ている。
release-check・browser-smoke 17項目・browser-mouse 12項目・9ステージ通し合格。
